# Ablations

Repeatable measurements against what SHIPS. Everything here answers a standing question about a production choice — the kind of figure `docs/methodology.md`, `docs/mirt_benchmark.md` or `pwa/about.html` quotes — and is meant to be re-run after a refit rather than archaeologically recovered. A script arrives here when its output is evidence for a decision the system already made; a script that explores a decision not yet made belongs in `auxiliary/rating_dev/`.

Contract for a script in this directory:

- **Repeatable**: seeded, deterministic given its inputs, runnable as `./.venv/bin/python3 -m ablations.<name>` with defaults that reproduce the quoted figure.
- **Reads production artifacts by default** — the shipped model (`ratings/mirt_model.pt`), the shipped curves (`ratings/{rating_to_rank,rank_map,population_constants}.json`), the shared feature assembly (`utils.rating.features`), the packaged shards, the corpus, the local DB copy. No private restatement of the trunk, the feature order, the projection or a client formula; import the single-source helpers — `utils/rating/fitted_projection.py` for the per-cell chain, `utils/rating/` for the rest — so the measurement cannot drift from what ships. A candidate fit enters only as an explicitly named COMPARISON ARM (a `dev_runs/` checkpoint on the command line, never a default), projected through the same helpers at the block layout it was fitted on.
- **Self-describing output**: the printed table carries its own column meanings; a reader should not need the script to interpret the numbers.
- **Kept current**: when a refit or format change invalidates a figure a doc quotes from here, re-run the script and update the doc in the same pass.

**Import direction.** `pipeline/` and `utils/` never import from here, so this directory is a leaf on production, and nothing in `auxiliary/` imports from here either, nor anything here from `auxiliary/`. Anything a script here shares with a script there belongs in `utils/rating/` instead — the M curve, the couplings and the time dock are in `ratings_io`, the client-mirror solve-time window in `rank_surveys`.

## Figures the documents quote

A number that `pwa/about.html` or `docs/methodology.md` quotes is not typed into the document; it is a **figure** some `*_figures.py` module here emits, and it reaches the document through `ablations/figures.json`:

```bash
./.venv/bin/python3 -m ablations --tier about        # minutes, no GPU — everything the About page quotes
./.venv/bin/python3 -m ablations --tier methodology  # + the per-cell / torch measurements
./.venv/bin/python3 -m ablations --only corpus_figures
./.venv/bin/python3 -m ablations --check             # documents vs ledger, no measurement
./.venv/bin/python3 -m ablations --list              # producers, their keys, where each is quoted
```

- **The ledger (`figures.json`) is the record.** One entry per key: the raw `value`, a display `fmt`, the rendered `text`, the producer, its tier, and the snapshot it was measured on (commit, `MAX(id)` of the attempt log, `data_version`). Raw numbers are what is stored; `text` is derived and exists only so the build check needs no formatter. It is committed and never edited by hand — a figure changes by re-running its producer.
- **A document quotes a figure inside `<span data-fig="KEY">text</span>`**, and each document has ONE committed version: the key stays in the file, the span's text is the current value, and `python -m ablations` rewrites it and prints every span it changed. That printed diff is the review step — a figure that moves can invalidate the sentence around it ("inside its interval", "neither route is engaged"), which no rewriter can see, so read the sentences before committing. `about.html` carries each key once per language block; one run updates all four.
- **`npm run build` refuses to build while a span disagrees with the ledger** (`pwa/scripts/figures-check.mjs`), so a number cannot reach the site without a producer behind it, and a re-measured number cannot ship stale. The dev loop only warns.
- **A document dates its figures from the ledger, never by hand.** One overall claim at the top — `<span data-fig-measured="earliest">` and `<span data-fig-measured="latest">` — holds the first and last UTC day on which any figure that document quotes or guards was measured, taken over the ledger's per-key `measured.at` stamps. The range is the page's own, not the ledger's, and it widens whenever one tier is re-run without the others, which is the truthful reading: the cheap figures are fresher than the GPU-day ones. There are no per-claim dates. Every measuring run rewrites the two spans; `python -m ablations --sync` rewrites them (and the figure spans) from the ledger with no measurement, which is the remedy when a document changes what it quotes; `figures-check.mjs` recomputes the same range and fails the build on a disagreement.
- **A producer emits exactly the keys it owns**, declares a cost `TIER` (`about` < `methodology` < `refit`; `--tier X` runs everything at X or cheaper), exposes `figures()` and its own `main()` with a self-describing table, and **hard-fails on any surprise in its inputs** — a missing file, an unexpected column, a count that does not match its sibling artifact — rather than emitting a figure from a guess. A run is therefore also a check on the shipped artifacts it reads. The assertion is `_figures.require`, not `assert`.
- **A key names a claim, and a claim with no key is unbacked.** Keys are dotted lowercase (`rank.within1_pct`); the last segment must not read as a file suffix, because the methodology page's build-time scope check treats `x.txt` in the method chapters as a leaked file name.
- **A sentence whose wording depends on a figure it does not quote carries a GUARD**: `<!-- fig-guard: KEY OP NUMBER -->` (or `NUMBER OP KEY OP NUMBER`; OP is `== != < <= > >=`), an invisible comment placed beside the claim — the "and nothing else", "nearly every user", "on N of the K axes" phrasings that break when a value drifts. A guard injects nothing and never replaces a span; it is evaluated against the LEDGER's raw value — never by re-running a producer, so the check stays cheap whatever tier the guarded figure comes from, and it fires only when a re-measure lands outside the claim. `python -m ablations --check` and the tail of every measuring run evaluate them, `figures-check.mjs` fails the build on a violation, and the methodology page generator strips the comments before publishing. A violated guard is a sentence to rewrite, which no rewriter can do — that is the point. Grammar and authority: `_figures.py`.

## The rating + axes fit and the per-cell readings

- **`tail_conditioning_sensitivity.py`** — how much of the per-cell axis readings' WITHIN-PROBLEM structure (the tendency sign test and the availability null) depends on the per-problem tail conditioning, measured by projecting variation cells with the real tail against a fully-dropped tail. `--population picked` reruns it on the wrong moves players actually recorded instead of the uniform variation draw.
- **`tendency_split_half.py`** — which per-cell projection yields the more RELIABLE per-user tendency readings: the shipped tendency z computed on odd/even halves of each user's own errors, correlated across users per axis, fully paired between the two arms. Arm A is always the shipped fit on its full input; arm B defaults to the same fit with the tail dropped, and `--arm-b-model CKPT --arm-b-features BLOCKS` makes it a DIFFERENT fit read on its own full input instead — which is how a candidate feature set is scored on the readings rather than on the rating. Axes pair by index, so the candidate must have been taught the same rule bank in the same order.
- **`eval_error_null_models.py`** — the measurement behind the AVAILABILITY NULL: given that a user erred, which candidate null best predicts which wrong variation they picked (phase 1), and what each one does to the directional statistic the client reports (phase 2). Phase 2b is what ADJUDICATES, scoring the per-error directional log-loss the tendency test actually consumes — a null can win phase 1 and lose there, because concentrating the pick distribution says nothing about splitting the alternatives correctly above and below the answer. This is what retired the fixed 50% null the tendency test used to stand against. The default reads the production per-cell store; `--embeddings actbot --model CKPT --features BLOCKS` is the explicitly named comparison arm, projecting the cells through that dev checkpoint instead.
- **`tendency_null_variants.py`** — the mirror of `tendency_split_half`: hold the projection fixed and ask which error NULL yields the more stable per-user readings, paired over users per axis, parameter-free variants only. `fixed-0.5` is the CONTROL rather than a candidate — it scores as by far the most reliable arm precisely because it leaves the per-problem menu confound inside the statistic, which is the demonstration that split-half reliability is gameable by removing information and can only order candidates that have already passed the validity question.
- **`percell_variance.py`** — how much of the per-cell axis readings is MOVE-LOCAL: a one-way decomposition of each axis over a seeded problem sample's variation cells, within-problem (the only component the tendency sign test and the strength contrast can consume, both being within-problem comparisons) against between-problem, plus whether the answer sits off-centre among its own alternatives. Training supervises one target per problem at the correct cell, so nothing forces the within component to be large; this measures what a fit emitted. `--store` reads the production per-cell store (the default arm, resolved from `axes/per_cell*` so a retired sibling still reads), `--arm CKPT:BLOCKS` adds a dev fit projected on its own full input.

## The rating→rank map

- **`check_mapped_vs_declared_rank.py`** — end-to-end calibration of the SHIPPED mapping (not a refit): each survey user's 80%-clear rating, mapped through the curve and their server's coupling, bucketed against what they declared, plus both declaration-honesty routes against verified federation ratings. It drops the declarations `map_rating_to_rank` screened out before its final fit (`ratings/declaration_exclusions.csv`), so what it reports describes the declarations the mapping accepts. Run after every `map_rating_to_rank` refit — **the figures it prints are published in `pwa/about.html` in four languages**, and only `err_server` (time-adjusted, in that server's own units) is quotable. `--csv` also feeds `eval_equivalent_tournament_games --targets`.
- **`eval_rank_map_cv.py`** — the paired held-out CV harness behind the mapping's design choices: it validated the 2-month career-block anchors and rejected errors-in-variables weighting over each rating's CI.
- **`eval_equivalent_tournament_games.py`** — puts the shown rank's accuracy in units a Go player already has: how many tournament games a rating would need to be this good. Fits a stone-value curve to `data/reference/even_game_winrates.txt` (one joint fit across every grade × gap cell, so the +1..+4 columns bend as a stone's worth changes up the ladder — measured at roughly a quarter of a logit per stone in the mid kyus against three quarters in the dan range, so a dan game carries an order of magnitude more information), simulates a Swiss on that law, and sweeps the trailing window until its ρ / within-1 / within-2 match `check_mapped_vs_declared_rank`'s CSV. On the EGF-system declarations all five statistics land together at **15 ± 3 games** (`rank.games_equivalent` in the ledger) (the ± is a bootstrap over the declarations behind the target — the dominant term, since a curve point is already averaged over independent populations and rounds), and the pooled figure stays inside that margin under every sensitivity: link from the rating-indexed Se blocks instead of the declared-grade table, 20k dropped, our own user population as entrants, band-quantized vs continuous reference, peer vs ground-truth comparison. Two results about the simulation itself, both measured and both counter-intuitive: **pairing strictly by information is the wrong objective** — Fisher information peaks at equal strength, so it pairs nearest-neighbour, which leaves the field a chain that pins order while leaving the chain's own length unmeasured, and absolute rank error stops falling past ~20 games while ρ keeps rising (`--pair-mixing 0` reproduces it); and **a free windowed MLE does not exist** here, since a trailing window always separates somebody, so a population prior is required and renormalizing the mean does not substitute for it. Default `--compare peer` scores one x-game rating against a second independent one, which is like-for-like against a measurement whose other side is a self-declaration; `--compare truth` is the floor. `--targets --scope --link --population --games --compare`.

## The client's estimators

- **`skill_drift_fit.py`** — what each term of the Rank tab's career skill smoother (`pwa/js/skill-smoother.js`) is worth: three nested arms — the random walk alone, with the per-session form offset, and with the step variance saturating at a cap — each fitted by population maximum likelihood of every first-time attempt's outcome given the same player's earlier attempts, beside the shipped constants' own log-likelihood. Runs the shipped smoother under node (`skill_drift_fit.mjs`). The shipped constants are fitted by `pipeline.fit_population_constants`, not here.
- **`eval_recall_model.py`** — validates the shipped retention model against the attempt log: per-rung realized retention against the window ceiling, within-user contrasts, delivery. Produces every figure in `docs/methodology.md` §2.8's closing subsection; `recall_figures` reads its returned statistics into the ledger, so a refresh is one ledger run.


## The refit tier: panels

A refit-tier figure costs one or more full training runs, so its producer never trains. The measurement is a **panel** — a manifest under `panels/<name>.json` naming arms, each arm one invocation of `ablations.ablation_mirt`, which calls `pipeline.train_mirt.run(...)` — the shipped loop itself, every keyword defaulting to the production constant (the seam was verified by a bitwise pre/post comparison of a short-budget run) — with outputs redirected under `dev_runs/<panel>/<arm>/`, so an arm can never touch `ratings/` or `axes/`. **What an arm holds aside follows its stop unit**: a row arm holds the shipped share of rows and is calibrated on them exactly as production is, so its record carries `metrics.calibration`; an arm scored on whole held-out problems (or the `spread` sets) holds `HELD_ASIDE_FRAC` of them, trains on every row of the rest and runs UNCALIBRATED, scored as trained, because `train_mirt.run` refuses to calibrate on anything but randomly held rows. `ablations.run_panel <name>` runs a panel with arm-level resume (`--concurrency` to saturate a GPU whose single fit does not, `--smoke-epochs` for plumbing tests); on a card shared through a lock wrapper, `--gpu-lock <script>` (or `ONLYMOVE_GPU_LOCK`; off unless one is given) launches every arm as `<script> run <tag> -- <cmd>`, so each fit takes and releases the lock for itself and the pool holds one arm at a time, in `run_panel` and `run_queue` alike; `auxiliary/vast_orchestration.py ablate <name>` runs it on a rented box and rsyncs the records home incrementally. Each `<arm>.json` records the config, the metrics and the **pins** — attempt-log frontier, bank digests, machine identity. The refit producer (`refit_barrier_figures` is the worked example) reads the records and hard-fails on a short budget, on pins differing across arms, or on a pin no longer matching the current DB — a `fetch_database` between panel and producer moves the stop-row draw and voids every paired comparison, the `mirt_benchmark.md` rule mechanized. `--check` and the build stay instant regardless, since guards and spans evaluate against the last-measured ledger; a panel's cost is paid only when it is deliberately re-run. **Knobs on `ablation_mirt` are curated** — one flag per quantity a methodology claim turns on, added cluster by cluster together with the producer that reads it, never a general override surface — and comparisons are valid within one panel on one machine, which the pins enforce.

**A record also pins the REGIME it ran under** — the effective `epochs`, `lr_schedule` and the mutual-orthogonality term's weight and detachment (`ortho_axes`, `ortho_axes_detach`), the floor's source, and per stop unit the held share and whether the curve was calibrated on it, which are what a baseline change moves — and every producer requires one regime across the arms it reads (`panel_regime` in `_figures.py`; a panel that sweeps the ramp or the mutual term by design says so there and reads the swept value off its own records). A shipped arm's config is `{}` under any baseline, so the config alone cannot tell a record measured under a retired baseline from a current one; the regime pin can. A finished panel keeps its internal contrast across a baseline change and loses only comparability to arms measured under the new one, so its ledger values stand until it is re-measured. **Re-measuring a panel archives its records to `dev_runs/<panel>.<old regime>/` first** (the box and the local copy alike — the pool skips arms that have records, so an unarchived panel re-runs nothing), and a producer aborts on the half-re-measured panel in between, correctly. **Archive and push the new code with NO pool live on the box** — a pool idling on the queue re-reads it the moment the archive empties a panel and relaunches those arms with whatever code the box still holds, which is how a fresh panel acquires two old-regime records in the window between the archive and the code upload. The regime pins catch it after the fact; killing the pool first prevents it.

### Done — measured against what ships, replicated across seeds

Every one of these ran on rented GPU time through `auxiliary/vast_orchestration.py ablate`, with each configuration replicated so that a contrast smaller than a single run's own wander is never quoted as a finding.

- §1.3 — the activation width. 128 wins from both sides at every seed. Two details did NOT survive: widening costs about half what cutting does rather than "about as much", and the memorization slope signature holds at one seed and not the other. `panels/features.json`.
- §1.5, §1.14 — what fixes the axis basis, and what it costs. Untaught seeds barely agree; taught seeds agree nearly perfectly. On this panel's two paired seeds the taught fit predicts held-out problems BETTER than the same fit with the pull off (mutual term on in both) — the opposite sign to `axis_space`'s contrast, which pins the mutual term off and is what §1.14 quotes. `panels/seeds.json`.
- §1.7 — the slope barrier, which this panel retired (`SHALLOW_W` is 0). The blow-out without it is real, one-sided, and about the same size at every seed; the held-out likelihood does not see it — the fit without the barrier scores marginally better at every seed. Ten times the 0.3 weight has no resolved held-out cost and narrows the rating span at two seeds of three, so the tail's width follows the weight. The arm named `shipped` carries the barrier at 0.3; `barrier_off` is the configuration that ships. Every span is the arms' own as-trained rating (problem-held, uncalibrated). `panels/barrier.json`.
- §1.8, §3.5 — the learning rates. One shared rate does not diverge here and reads slightly better than the 33x split on every seed; a 10x ratio does not resolve; a slower network is slightly worse on every seed and plateaus at the same epoch. No contrast reaches a millinat. **The panel does not decide the split**: it scores held-out problems on uncalibrated fits, and on the production configuration's calibrated held-row loss (same rows, paired by initialisation) the shared rate is 1 mnat worse with the slope barrier at the one seed measured and, without it, 7 mnat worse at one seed and 1.7 better at another — the panel's unanimous sign is absent there, so the split stays. `panels/lr.json`.
- §1.8 — determinism, and the wander. Two panels ran the shipped configuration independently and agree bitwise; the shipped fit's own held-out score wanders wider than most contrasts this document quotes, which is now stated as the rule for reading all of them. `refit_determinism_figures.py`.
- §2.9 — the reliability control. The retired fixed-even null is the most split-half reliable arm on every axis, which is why reliability cannot select a null.
- §1.8, §3.5 — the schedule and the budget. A cosine decay to zero at 7000 epochs ships: parity with the constant rate on held-out problems, run-to-run spread about halved, and the budget bounded above by overfitting the decay locks in (12000 is worse than 7000 by more than the spread; the constant rate turns the same way past its own budget). Compared at matched WORK, never at matched epochs. `panels/schedule.json` — the one panel that is not re-measured under the new baseline, being the measurement of it.
- §1.3 — the answer-conditioning claim. Parity on both stop units, sign-inconsistent across seeds, so the shipped input stands. `panels/blocks.json`.
- §1.5 — weight decay and the two dropout sites. Decay does not substitute for dropout; beside dropout it is better on held-out problems at both seeds (a baseline candidate, not yet adopted); the two dropout sites are super-additive. `panels/regularization.json`.
- §1.14 — the axis count. Four, six and seven separate by less than the run-to-run spread on the combined likelihood; the axis increment alone rises with the count mechanically. `panels/axis_count.json`.
- §1.5 — the rating-orthogonality penalty. Unpenalized ends leak; closing the rating alone moves the leak onto the slope, almost all of it on one axis at both seeds; the whole-axis form understates what its ends carry at every seed, while the per-end fit's worst end is lower only on average. The floor column is constant under the global floor and reads zero throughout. `panels/penalty.json`.
- §1.5, §1.14 — which terms on the loadings need the trunk. The teaching pull and the rating-orthogonality penalty both need it, at eight seeds each; a mutual-orthogonality penalty on the DETACHED readout is better on every count the panel reads and is the baseline; the anisotropic ridge is measured-rejected. `panels/detach.json`.
- §1.5, §1.10 — the per-problem spread: how far a problem's true logit sits off the fitted curve, read from outcomes that agree across different players on one problem. Sizeable on problems held out whole, at every fit; training on half a problem's attempts narrows it only a little (smaller at every fit, inside each fit's own interval); a shrunken per-problem estimate would recover only a minority of it at the log's density, which is the support for §1.10's "no per-problem correction". The holdout is the trainer's `spread` stop unit, drawn BEFORE the fit among problems with enough training rows to carry a cross-player pair; attempts arriving after a shipped fit are the obvious holdout and the wrong one, since their players' abilities are stale or have to be re-fitted on the rows being scored. Three seeds, each drawing its own holdout, because it is a magnitude; run on a local GPU rather than rented time. `panels/problem_spread.json`, `refit_spread_figures.py`.
- §1.5, §1.10 — whether the curve's two levels come back the same from one fit to the next. Every arm is the shipped fit, row-held and calibrated, read under three curves over the same held rows: as trained, the plain calibration, and the shipped uncertainty-averaged one. The calibrated LAPSE and the rates at the curve's two ends reproduce, the held-loss gains of calibrating and of averaging over ability uncertainty are positive at every fit, and the plain curve reads both levels higher at every fit. The calibrated FLOOR is only steadier than the trained one, not steady: its sd is about half the trained floor's, no smaller with the held draw pinned than with it moving, and on one held draw it moves with the slope multiplier almost exactly — the scatter is the frozen fit's, along a floor-against-slope-scale direction the held rows price weakly. Two sets because the two questions want different draws: `draw_s*` moves everything with the seed (a magnitude), `init_s*` pins the held draw and basis to seed 0's (paired, the fit's own scatter). Run on a local GPU. `panels/levels.json`, `refit_levels_figures.py`.

### Re-measurement under the current baseline

The baseline is cosine@7000 with the detached mutual term, one global floor, a third of the rows held out and calibrated on, the 33x rate split and no slope barrier. The six panels re-measured at K = 9 and width 512 (`seeds`, `problem_spread`, `barrier`, `penalty`, `lr`, `blocks`) ran with the barrier at 0.3; every record pins its rates and barrier weight, and a panel straddling either is refused. Every panel above was measured with a floor per problem off the trunk and no calibration — which is what makes four producers' PREMISES stale rather than merely their values: `published_params_figures`' floor figures (a distribution of per-problem floors), `refit_slope_scale_figures` (a pivot-at-the-rating multiplier the calibration supersedes), `refit_barrier_figures`' undefined-rating counts (problems whose own floor crosses the calibration probability — retired with the per-problem floor) and `serve_log_figures`' `serve.fitted_ceiling` / `serve.lapse_bound` / `serve.lapse_headroom` (an in-sample bound on the lapse); the documents quote none of them.
