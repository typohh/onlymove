# Ablations

Repeatable measurements against what SHIPS. Everything here answers a standing question about a production choice — the kind of figure `docs/methodology.md`, `docs/mirt_benchmark.md` or `pwa/about.html` quotes — and is meant to be re-run after a refit rather than archaeologically recovered. A script arrives here when its output is evidence for a decision the system already made; a script that explores a decision not yet made belongs in `auxiliary/rating_dev/`.

Contract for a script in this directory:

- **Repeatable**: seeded, deterministic given its inputs, runnable as `./.venv/bin/python3 -m ablations.<name>` with defaults that reproduce the quoted figure.
- **Reads production artifacts by default** — the shipped model (`ratings/mirt_model.pt`), the shipped curves (`ratings/{rating_to_rank,rank_map,population_constants}.json`), the shared feature assembly (`utils.rating.features`), the packaged shards, the corpus, the local DB copy. No private restatement of the trunk, the feature order, the projection or a client formula; import the single-source helpers — `_projection.py` for the per-cell chain, `utils/rating/` for the rest — so the measurement cannot drift from what ships. A candidate fit enters only as an explicitly named COMPARISON ARM (a `dev_runs/` checkpoint on the command line, never a default), projected through the same helpers at the block layout it was fitted on.
- **Self-describing output**: the printed table carries its own column meanings; a reader should not need the script to interpret the numbers.
- **Kept current**: when a refit or format change invalidates a figure a doc quotes from here, re-run the script and update the doc in the same pass.

**Import direction.** `pipeline/` and `utils/` never import from here, so this directory is a leaf on production, and nothing in `auxiliary/` imports from here either. ONE edge crosses the other way: `eval_rank_endpoint_bias` imports the Rank-tab replica from `auxiliary.recreate_rank_graph` rather than restating the pooled 4PL. Anything a script here shares with a script there belongs in `utils/rating/` instead — the M curve, the couplings and the time dock are in `ratings_io`, the client-mirror solve-time window in `rank_surveys`.

## The rating + axes fit and the per-cell readings

- **`tail_conditioning_sensitivity.py`** — how much of the per-cell axis readings' WITHIN-PROBLEM structure (the tendency sign test and the availability null) depends on the per-problem tail conditioning, measured by projecting variation cells with the real tail against a fully-dropped tail. `--population picked` reruns it on the wrong moves players actually recorded instead of the uniform variation draw.
- **`tendency_split_half.py`** — which per-cell projection yields the more RELIABLE per-user tendency readings: the shipped tendency z computed on odd/even halves of each user's own errors, correlated across users per axis, fully paired between the two arms. Arm A is always the shipped fit on its full input; arm B defaults to the same fit with the tail dropped, and `--arm-b-model CKPT --arm-b-features BLOCKS` makes it a DIFFERENT fit read on its own full input instead — which is how a candidate feature set is scored on the readings rather than on the rating. Axes pair by index, so the candidate must have been taught the same rule bank in the same order.
- **`eval_error_null_models.py`** — the measurement behind the AVAILABILITY NULL: given that a user erred, which candidate null best predicts which wrong variation they picked (phase 1), and what each one does to the directional statistic the client reports (phase 2). Phase 2b is what ADJUDICATES, scoring the per-error directional log-loss the tendency test actually consumes — a null can win phase 1 and lose there, because concentrating the pick distribution says nothing about splitting the alternatives correctly above and below the answer. This is what retired the fixed 50% null the tendency test used to stand against. `--embeddings shipped` reads the production per-cell store; the default projects the cells through a named dev checkpoint.
- **`tendency_null_variants.py`** — the mirror of `tendency_split_half`: hold the projection fixed and ask which error NULL yields the more stable per-user readings, paired over users per axis, parameter-free variants only. `fixed-0.5` is the CONTROL rather than a candidate — it scores as by far the most reliable arm precisely because it leaves the per-problem menu confound inside the statistic, which is the demonstration that split-half reliability is gameable by removing information and can only order candidates that have already passed the validity question.
- **`percell_variance.py`** — how much of the per-cell axis readings is MOVE-LOCAL: a one-way decomposition of each axis over a seeded problem sample's variation cells, within-problem (the only component the tendency sign test and the strength contrast can consume, both being within-problem comparisons) against between-problem, plus whether the answer sits off-centre among its own alternatives. Training supervises one target per problem at the correct cell, so nothing forces the within component to be large; this measures what a fit emitted. `--store` reads the production per-cell store (the default arm, resolved from `axes/per_cell*` so a retired sibling still reads), `--arm CKPT:BLOCKS` adds a dev fit projected on its own full input.
- **`eval_score_gap_axis.py`** — between-user predictive power of the best-vs-second-best score-gap axis, the measure-rejected candidate for a single non-embedding weakness axis: population effect, chronological split-half between-user structure, walk-forward kappa, and whether slower players do relatively better on tight margins. `--feature wr_gap` is the winrate comparator, `--feature joint` fits both.

## The rating→rank map

- **`check_mapped_vs_declared_rank.py`** — end-to-end calibration of the SHIPPED mapping (not a refit): each survey user's 80%-clear rating, mapped through the curve and their server's coupling, bucketed against what they declared, plus both declaration-honesty routes against verified federation ratings. Run after every `map_rating_to_rank` refit — **the figures it prints are published in `pwa/about.html` in four languages**, and only `err_server` (time-adjusted, in that server's own units) is quotable. `--csv` also feeds `eval_equivalent_tournament_games --targets`.
- **`eval_rank_map_cv.py`** — the paired held-out CV harness behind the mapping's design choices: it validated the 2-month career-block anchors and rejected errors-in-variables weighting over each rating's CI.
- **`eval_equivalent_tournament_games.py`** — puts the shown rank's accuracy in units a Go player already has: how many tournament games a rating would need to be this good. Fits a stone-value curve to `data/reference/even_game_winrates.txt` (one joint fit across every grade × gap cell, so the +1..+4 columns bend as a stone's worth changes up the ladder — measured at roughly a quarter of a logit per stone in the mid kyus against three quarters in the dan range, so a dan game carries an order of magnitude more information), simulates a Swiss on that law, and sweeps the trailing window until its ρ / within-1 / within-2 match `check_mapped_vs_declared_rank`'s CSV. On the EGF-system declarations all five statistics land together at **16 ± 3 games** (the ± is a bootstrap over the declarations behind the target — the dominant term, since a curve point is already averaged over independent populations and rounds), and the pooled figure stays inside that margin under every sensitivity: link from the rating-indexed Se blocks instead of the declared-grade table, 20k dropped, our own user population as entrants, band-quantized vs continuous reference, peer vs ground-truth comparison. Two results about the simulation itself, both measured and both counter-intuitive: **pairing strictly by information is the wrong objective** — Fisher information peaks at equal strength, so it pairs nearest-neighbour, which leaves the field a chain that pins order while leaving the chain's own length unmeasured, and absolute rank error stops falling past ~20 games while ρ keeps rising (`--pair-mixing 0` reproduces it); and **a free windowed MLE does not exist** here, since a trailing window always separates somebody, so a population prior is required and renormalizing the mean does not substitute for it. Default `--compare peer` scores one x-game rating against a second independent one, which is like-for-like against a measurement whose other side is a self-declaration; `--compare truth` is the floor. `--targets --scope --link --population --games --compare`.

## The client's estimators

- **`eval_rank_endpoint_bias.py`** — picks `SLOPE_PRIOR_SD` for the Rank-tab graph's local-linear boundary fix and measures how much right-edge lag it removes, scored against an interior two-sided kernel that has no boundary lag of its own. Imports the replica from `auxiliary.recreate_rank_graph`.
- **`eval_recall_model.py`** — validates the shipped retention model against the attempt log: per-rung realized retention against the window ceiling, within-user contrasts, delivery. Produces every figure in `docs/methodology.md` §2.8's closing subsection; re-run it to refresh them.

## The activation encoder

Both read RAW per-problem npz, which the shipped store no longer holds — a re-run needs `extract_activations --raw --out-dir` in place of it.

- **`encoder_m_sweep.py`** — chooses `ACT_ENCODER_DIM` by measurement: an M-spectrum scan, plus a simulated future refit (encoder fitted on half the problems, downstream 128-PCA fitted inside that M-space, scored on rows the encoder never saw) against the counterfactual full-space PCA.
- **`encoder_altstats_gate.py`** — whether encoder truncation moves the availability null, by running the SAME fitted chain twice per cell (raw vector vs the encoded store's vector reconstructed back to raw space) with no refit anywhere. The gate passes when the flip rate sits at or below the cross-projection reference rate `emit_alt_stats` already records.
