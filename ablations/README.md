# Ablations

Repeatable measurements against what SHIPS. Everything here answers a standing question about a production choice — the kind of figure `docs/methodology.md`, `docs/mirt_benchmark.md` or `pwa/about.html` quotes — and is meant to be re-run after a refit rather than archaeologically recovered. A script arrives here when its output is evidence for a decision the system already made; a script that explores a decision not yet made belongs in `auxiliary/rating_dev/`.

Contract for a script in this directory:

- **Repeatable**: seeded, deterministic given its inputs, runnable as `./.venv/bin/python3 -m ablations.<name>` with defaults that reproduce the quoted figure.
- **Reads production artifacts by default** — the shipped model (`ratings/mirt_model.pt`), the shipped curves (`ratings/{rating_to_rank,rank_map,population_constants}.json`), the shared feature assembly (`utils.rating.features`), the packaged shards, the corpus, the local DB copy. No private restatement of the trunk, the feature order, the projection or a client formula; import the single-source helpers — `utils/rating/fitted_projection.py` for the per-cell chain, `utils/rating/` for the rest — so the measurement cannot drift from what ships. A candidate fit enters only as an explicitly named COMPARISON ARM (a `dev_runs/` checkpoint on the command line, never a default), projected through the same helpers at the block layout it was fitted on.
- **Self-describing output**: the printed table carries its own column meanings; a reader should not need the script to interpret the numbers.
- **Kept current**: when a refit or format change invalidates a figure a doc quotes from here, re-run the script and update the doc in the same pass.

**Import direction.** `pipeline/` and `utils/` never import from here, so this directory is a leaf on production, and nothing in `auxiliary/` imports from here either. ONE edge crosses the other way: `eval_rank_endpoint_bias` imports the Rank-tab replica from `auxiliary.recreate_rank_graph` rather than restating the pooled 4PL. Anything a script here shares with a script there belongs in `utils/rating/` instead — the M curve, the couplings and the time dock are in `ratings_io`, the client-mirror solve-time window in `rank_surveys`.

## Figures the documents quote

A number that `pwa/about.html` or `docs/methodology.md` quotes is not typed into the document; it is a **figure** some `*_figures.py` module here emits, and it reaches the document through `ablations/figures.json`:

```bash
./.venv/bin/python3 -m ablations --tier about        # minutes, no GPU — everything the About page quotes
./.venv/bin/python3 -m ablations --tier methodology  # + the per-cell / torch measurements
./.venv/bin/python3 -m ablations --only corpus_figures
./.venv/bin/python3 -m ablations --check             # documents vs ledger, no measurement
./.venv/bin/python3 -m ablations --list              # producers, their keys, where each is quoted
```

- **The ledger (`figures.json`) is the record.** One entry per key: the raw `value`, a display `fmt`, the rendered `text`, the producer, its tier, and the snapshot it was measured on (commit, `MAX(id)` of the attempt log, `data_version`). Raw numbers are what is stored; `text` is derived and exists only so the build check needs no formatter. It is committed and never edited by hand — a figure changes by re-running its producer.
- **A document quotes a figure inside `<span data-fig="KEY">text</span>`**, and each document has ONE committed version: the key stays in the file, the span's text is the current value, and `python -m ablations` rewrites it and prints every span it changed. That printed diff is the review step — a figure that moves can invalidate the sentence around it ("inside its interval", "neither route is engaged"), which no rewriter can see, so read the sentences before committing. `about.html` carries each key once per language block; one run updates all four.
- **`npm run build` refuses to build while a span disagrees with the ledger** (`pwa/scripts/figures-check.mjs`), so a number cannot reach the site without a producer behind it, and a re-measured number cannot ship stale. The dev loop only warns.
- **A producer emits exactly the keys it owns**, declares a cost `TIER` (`about` < `methodology` < `refit`; `--tier X` runs everything at X or cheaper), exposes `figures()` and its own `main()` with a self-describing table, and **hard-fails on any surprise in its inputs** — a missing file, an unexpected column, a count that does not match its sibling artifact — rather than emitting a figure from a guess. A run is therefore also a check on the shipped artifacts it reads. The assertion is `_figures.require`, not `assert`.
- **A key names a claim, and a claim with no key is unbacked.** Keys are dotted lowercase (`rank.within1_pct`); the last segment must not read as a file suffix, because the methodology page's build-time scope check treats `x.txt` in the method chapters as a leaked file name.
- **A sentence whose wording depends on a figure it does not quote carries a GUARD**: `<!-- fig-guard: KEY OP NUMBER -->` (or `NUMBER OP KEY OP NUMBER`; OP is `== != < <= > >=`), an invisible comment placed beside the claim — the "and nothing else", "nearly every user", "on N of the K axes" phrasings that break when a value drifts. A guard injects nothing and never replaces a span; it is evaluated against the LEDGER's raw value — never by re-running a producer, so the check stays cheap whatever tier the guarded figure comes from, and it fires only when a re-measure lands outside the claim. `python -m ablations --check` and the tail of every measuring run evaluate them, `figures-check.mjs` fails the build on a violation, and the methodology page generator strips the comments before publishing. A violated guard is a sentence to rewrite, which no rewriter can do — that is the point. Grammar and authority: `_figures.py`.

Producers: **`corpus_figures.py`** (the published index, `pwa/lookup.txt`, whole and per size, plus the truncated-id collision arithmetic at the current count; checks it against `problem_params.bin`), **`rank_calibration_figures.py`** (the About page's rank-accuracy figures: the survey rho and its player-bootstrap margin, the within-one/two-rank shares, and the equivalent-tournament-games figure matched on the machine-verified EGF ratings — drives `check_mapped_vs_declared_rank` and `eval_equivalent_tournament_games`, which is why both take an `argv` and the latter returns its match), **`published_params_figures.py`** (extremes of the shipped per-problem triple, and the clamp-to-calibration floor band behind the "catches the sentinel problems and nothing else" guard), **`motif_null_figures.py`** (drives `eval_error_null_models` and reads its phase-2 statistics at the shipped visits-linear null: the population-lean sign reversals against the fixed even split, and the flag shares on the most menu-skewed axis), **`recall_figures.py`** (drives `eval_recall_model` and reads its returned statistics: the per-rung clear rates, the held-out recalibration, the within-user odds ratios and their heterogeneity, the first-success-step figures, the clean-chain exclusion, and the schedule-invariant matched-relative-interval contrast that stays comparable across a scheduling change), **`curve_shape_figures.py`** (geometry of the shipped rating→rank curve and the SE-floor curve, converted to rank units through the packaging step's own mirror of the client floor formula), **`corpus_claim_figures.py`** (the never-attempted share, the axis-tail attempt enrichment over `per_problem.csv` extremes, the pass-variation position from the published cells sidecars, and the ownership-swing pass baseline), **`serve_log_figures.py`** (the model-free half: raw first-time clear rates by history position and the rank window's span distribution; and the ratings-joined half: the opening serve-gap trend, the gap-binned clear rates with the lapse bound, and the recorded-history rank-gap spread against per-block and career user ratings), **`client_estimator_figures.py`** (the onboarding serve-margin simulation, the information-slot extreme-value bias and the community histogram's gate shift — measured by running the REAL client modules under node via its `client_estimators.mjs` helper, `pwa/shared/rank-window.js` and `irt.js` imported unmodified, with only the `state`-entangled pieces mirrored and named), **`rank_map_arm_figures.py`** (the mapping's comparison arms, fit in memory: the declaration screen's curve movement and posterior bar, and the federation-pinned latent's headline shift), **`axes_fit_figures.py`** (the shipped fit's own per-tail rating leakage, axis-position–ability correlations, and hinged taught-end agreement), **`cast_error_figures.py`** (the published per-cell fp16 bounds and within-problem contrast, plus a bit-identity audit of published blocks against the store).

`motif_null_figures` additionally reads phase 2b's adjudication at the shipped null (depth-weighting vs equal counting, and the fitted arm's residual gain), the rank-share contrast between the population-average and per-problem-null readings, and the cross-projection rates recomputed from the published artifacts with packaging's own mass arithmetic.

## The rating + axes fit and the per-cell readings

- **`tail_conditioning_sensitivity.py`** — how much of the per-cell axis readings' WITHIN-PROBLEM structure (the tendency sign test and the availability null) depends on the per-problem tail conditioning, measured by projecting variation cells with the real tail against a fully-dropped tail. `--population picked` reruns it on the wrong moves players actually recorded instead of the uniform variation draw.
- **`tendency_split_half.py`** — which per-cell projection yields the more RELIABLE per-user tendency readings: the shipped tendency z computed on odd/even halves of each user's own errors, correlated across users per axis, fully paired between the two arms. Arm A is always the shipped fit on its full input; arm B defaults to the same fit with the tail dropped, and `--arm-b-model CKPT --arm-b-features BLOCKS` makes it a DIFFERENT fit read on its own full input instead — which is how a candidate feature set is scored on the readings rather than on the rating. Axes pair by index, so the candidate must have been taught the same rule bank in the same order.
- **`eval_error_null_models.py`** — the measurement behind the AVAILABILITY NULL: given that a user erred, which candidate null best predicts which wrong variation they picked (phase 1), and what each one does to the directional statistic the client reports (phase 2). Phase 2b is what ADJUDICATES, scoring the per-error directional log-loss the tendency test actually consumes — a null can win phase 1 and lose there, because concentrating the pick distribution says nothing about splitting the alternatives correctly above and below the answer. This is what retired the fixed 50% null the tendency test used to stand against. The default reads the production per-cell store; `--embeddings actbot --model CKPT --features BLOCKS` is the explicitly named comparison arm, projecting the cells through that dev checkpoint instead.
- **`tendency_null_variants.py`** — the mirror of `tendency_split_half`: hold the projection fixed and ask which error NULL yields the more stable per-user readings, paired over users per axis, parameter-free variants only. `fixed-0.5` is the CONTROL rather than a candidate — it scores as by far the most reliable arm precisely because it leaves the per-problem menu confound inside the statistic, which is the demonstration that split-half reliability is gameable by removing information and can only order candidates that have already passed the validity question.
- **`percell_variance.py`** — how much of the per-cell axis readings is MOVE-LOCAL: a one-way decomposition of each axis over a seeded problem sample's variation cells, within-problem (the only component the tendency sign test and the strength contrast can consume, both being within-problem comparisons) against between-problem, plus whether the answer sits off-centre among its own alternatives. Training supervises one target per problem at the correct cell, so nothing forces the within component to be large; this measures what a fit emitted. `--store` reads the production per-cell store (the default arm, resolved from `axes/per_cell*` so a retired sibling still reads), `--arm CKPT:BLOCKS` adds a dev fit projected on its own full input.

## The rating→rank map

- **`check_mapped_vs_declared_rank.py`** — end-to-end calibration of the SHIPPED mapping (not a refit): each survey user's 80%-clear rating, mapped through the curve and their server's coupling, bucketed against what they declared, plus both declaration-honesty routes against verified federation ratings. It drops the declarations `map_rating_to_rank` screened out before its final fit (`ratings/declaration_exclusions.csv`), so what it reports describes the declarations the mapping accepts. Run after every `map_rating_to_rank` refit — **the figures it prints are published in `pwa/about.html` in four languages**, and only `err_server` (time-adjusted, in that server's own units) is quotable. `--csv` also feeds `eval_equivalent_tournament_games --targets`.
- **`eval_rank_map_cv.py`** — the paired held-out CV harness behind the mapping's design choices: it validated the 2-month career-block anchors and rejected errors-in-variables weighting over each rating's CI.
- **`eval_equivalent_tournament_games.py`** — puts the shown rank's accuracy in units a Go player already has: how many tournament games a rating would need to be this good. Fits a stone-value curve to `data/reference/even_game_winrates.txt` (one joint fit across every grade × gap cell, so the +1..+4 columns bend as a stone's worth changes up the ladder — measured at roughly a quarter of a logit per stone in the mid kyus against three quarters in the dan range, so a dan game carries an order of magnitude more information), simulates a Swiss on that law, and sweeps the trailing window until its ρ / within-1 / within-2 match `check_mapped_vs_declared_rank`'s CSV. On the EGF-system declarations all five statistics land together at **15 ± 3 games** (`rank.games_equivalent` in the ledger) (the ± is a bootstrap over the declarations behind the target — the dominant term, since a curve point is already averaged over independent populations and rounds), and the pooled figure stays inside that margin under every sensitivity: link from the rating-indexed Se blocks instead of the declared-grade table, 20k dropped, our own user population as entrants, band-quantized vs continuous reference, peer vs ground-truth comparison. Two results about the simulation itself, both measured and both counter-intuitive: **pairing strictly by information is the wrong objective** — Fisher information peaks at equal strength, so it pairs nearest-neighbour, which leaves the field a chain that pins order while leaving the chain's own length unmeasured, and absolute rank error stops falling past ~20 games while ρ keeps rising (`--pair-mixing 0` reproduces it); and **a free windowed MLE does not exist** here, since a trailing window always separates somebody, so a population prior is required and renormalizing the mean does not substitute for it. Default `--compare peer` scores one x-game rating against a second independent one, which is like-for-like against a measurement whose other side is a self-declaration; `--compare truth` is the floor. `--targets --scope --link --population --games --compare`.

## The client's estimators

- **`eval_rank_endpoint_bias.py`** — picks `SLOPE_PRIOR_SD` for the Rank-tab graph's local-linear boundary fix and measures how much right-edge lag it removes, scored against an interior two-sided kernel that has no boundary lag of its own. Imports the replica from `auxiliary.recreate_rank_graph`.
- **`eval_recall_model.py`** — validates the shipped retention model against the attempt log: per-rung realized retention against the window ceiling, within-user contrasts, delivery. Produces every figure in `docs/methodology.md` §2.8's closing subsection; `recall_figures` reads its returned statistics into the ledger, so a refresh is one ledger run.

## The activation encoder

Both read RAW per-problem npz, which the shipped store no longer holds — a re-run needs `extract_activations --raw --out-dir` in place of it.

- **`encoder_m_sweep.py`** — chooses `ACT_ENCODER_DIM` by measurement: an M-spectrum scan, plus a simulated future refit (encoder fitted on half the problems, downstream 128-PCA fitted inside that M-space, scored on rows the encoder never saw) against the counterfactual full-space PCA.
- **`encoder_altstats_gate.py`** — whether encoder truncation moves the availability null, by running the SAME fitted chain twice per cell (raw vector vs the encoded store's vector reconstructed back to raw space) with no refit anywhere. The gate passes when the flip rate sits at or below the cross-projection reference rate `emit_alt_stats` already records.

## The refit tier: panels

A refit-tier figure costs one or more full training runs, so its producer never trains. The measurement is a **panel** — a manifest under `panels/<name>.json` naming arms, each arm one invocation of `ablations.ablation_mirt`, which calls `pipeline.train_mirt.run(...)` — the shipped loop itself, every keyword defaulting to the production constant (the seam was verified by a bitwise pre/post comparison of a short-budget run) — with outputs redirected under `dev_runs/<panel>/<arm>/`, so an arm can never touch `ratings/` or `axes/`. `ablations.run_panel <name>` runs a panel with arm-level resume (`--concurrency` to saturate a GPU whose single fit does not, `--smoke-epochs` for plumbing tests); `vast_orchestration.py ablate <name>` runs it on a rented box and rsyncs the records home incrementally. Each `<arm>.json` records the config, the metrics and the **pins** — attempt-log frontier, bank digests, machine identity. The refit producer (`refit_barrier_figures` is the worked example) reads the records and hard-fails on a short budget, on pins differing across arms, or on a pin no longer matching the current DB — a `fetch_database` between panel and producer moves the stop-row draw and voids every paired comparison, the `mirt_benchmark.md` rule mechanized. `--check` and the build stay instant regardless, since guards and spans evaluate against the last-measured ledger; a panel's cost is paid only when it is deliberately re-run. **Knobs on `ablation_mirt` are curated** — one flag per quantity a methodology claim turns on, added cluster by cluster together with the producer that reads it, never a general override surface — and comparisons are valid within one panel on one machine, which the pins enforce.
